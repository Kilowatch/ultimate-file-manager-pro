## 2. Confirmed Decisions

### 1. Scope of Escape Sequence Sanitization Across All Locales
- **Decision:** Comprehensive Sanitization.
- **Actions:**
  1. **Bullet Separators (`\\u2022`):** Replace `%1$s \u2022 %2$s` and `%1$s \\u2022 %2$s` with literal UTF-8 bullet `%1$s • %2$s` for `fav_protocol_type_format` and `devicetypelabel_u2022_devicelastip` across default `values/strings.xml` and all 18 translated `values-*/strings.xml` files.
  2. **Ellipsis (`\\u2026`):** Replace `\u2026` and `\\u2026` with literal UTF-8 horizontal ellipsis `…` (`tile_color_copy_to`, `properties_calculating_size`, `opening_file`) across all affected language files.
  3. **Non-Breaking Spaces (`\\u00a0`):** Replace `\\u00a0` with standard/non-breaking space in `values-fr/strings.xml` (`use_remote_failed_message`).
  4. **Stray Newline Backslashes (`\\\n`):** Clean up stray `\\\n` in `values-ru/strings.xml`.
  5. **Double-Escaped Quotes and Apostrophes:** Clean up over-escaped quotes (`\\\"` $\to$ `\"`) and apostrophes (`\\\'` $\to$ `\'`) across all translation files so that literal backslashes do not leak into UI dialogs in Arabic, French, German, Russian, etc.

### 2. Translation Cache & State File Synchronization & Script Hardening
- **Decision:** Synchronize `app/src/main/res/.translate_cache/snapshot.json` and `app/src/main/res/.translation_state.json`, and update `translate_strings.py`.
- **Reasoning:** Prevents automated translation tools or subsequent pipeline runs from re-introducing stale `\\u2022` and double-escaped strings. Specifically update `translate_strings.py` to:
  1. Decode incoming `\\+uXXXX` to native UTF-8 characters prior to translation.
  2. Preserve native UTF-8 characters (`•`, `…`, non-breaking space) without converting to backslash escapes.
  3. Prevent backslash compounding on quotes and apostrophes (`\\\"`, `\\\'`).
  4. Post-process translated output before emission to guarantee zero unrendered `\\u` escapes or malformed punctuation.
